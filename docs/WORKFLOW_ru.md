# Рабочая инструкция (RU)

Публичное описание проекта на английском — в [README.md](../README.md). Здесь — как запускать и что важно помнить.

## Ключи API

| Источник | Что даёт | Ключ |
|---|---|---|
| **ENTSO-E** | цены на сутки вперёд, прогноз нагрузки, прогноз ветра и солнца, факт нагрузки | security token |
| **AGSI+** | заполненность газовых хранилищ Германии | бесплатный API key |
| **Open-Meteo** | исторические погодные данные | не нужен |
| **Yahoo Finance** | газ TTF, грубый прокси для CO₂ | не нужен, источник неофициальный |

Ключи лежат только в `.env` (он в `.gitignore`). Шаблон — `.env.example`.

## Окружение

```bash
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
```

В VS Code: Ctrl+Shift+P → «Python: Select Interpreter» → `.venv`. Для ноутбуков выбери ядро
**energy-price-forecast (.venv)** (зарегистрировано командой
`python -m ipykernel install --sys-prefix --name energy-price-forecast`).

**Windows-консоль:** если скрипт падает с `UnicodeEncodeError: 'charmap'`, это кодировка терминала, не данные.
Запускай с `set PYTHONUTF8=1` (cmd) или `$env:PYTHONUTF8=1` (PowerShell).

## Главное правило: никакой утечки будущего

Аукцион на день D закрывается в 12:00 CET дня D-1. В признаках — только то, что известно к этому моменту:

| Ряд | Что можно взять для дня D | Где задано |
|---|---|---|
| цены | весь день D-1 и раньше, по (дню поставки, местному часу) | `features.py` |
| прогнозы нагрузки/ВИЭ от TSO | на день D | `build_dataset.py` |
| TTF, CO₂-прокси | закрытие за D-2 (закрытие D-1 — после аукциона) | `MARKET_LAG_DAYS = 2` |
| хранилища AGSI | газовый день D-3 (публикуется вечером следующего дня) | `STORAGE_LAG_DAYS = 3` |
| фактическая нагрузка, фактическая погода | **нельзя**, только анализ | — |

Что было исправлено относительно первой версии: TTF и хранилища сдвигались на 1 день (утечка), фактическая погода шла
в таблицу как признак (это «идеальный прогноз погоды»). Тесты в `tests/test_leakage.py` ловят такие ошибки.

**Никаких прогнозов цены с сайтов** (биржи, аналитики, агрегаторы) — только фактические цены и прогнозы
фундаментальных факторов от TSO, которые реально есть у трейдера на момент аукциона.

## Как учитываем войну 2026 года

* Начало кризиса — 28.02.2026 (`CRISIS_START` в `config.py`), таймлайн событий — `src/events.py` с источниками.
* События — **только подписи на графиках**, в модель не идут: модель не знает о войне, она видит только цены газа.
* Все сравнения «до/после» — на **одном и том же календарном окне** 2025 и 2026 годов, иначе сезонность
  (солнце летом, отопление зимой) смешивается с эффектом кризиса.
